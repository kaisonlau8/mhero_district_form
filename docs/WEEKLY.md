# 猛士周报导入

周报和每天 08:30 的 7 张源表不是同一套数。经营收款、同比环比、季度累计主表都要单独导入。本轮没有新的定时任务，也不会改原来的 `08:30`。

页面：登录后打开「报表 → 猛士周报」。管理员在「导入 Excel」上传。命令行：

```bash
python -m reportdb.weekly_import operation \
  --file 服务经营报表.xlsx \
  --week 2026-11-16 \
  --period-start 2026-11-16 \
  --period-end 2026-11-19 \
  --exported-at "2026-11-20 14:25:35" \
  --timezone +08:00

python -m reportdb.weekly_import kpi \
  --file 服务管理主表.xlsx \
  --week 2026-11-16 \
  --as-of 2026-11-20 \
  --exported-at "2026-11-20 14:25:35"
```

经营文件按 DMS 的「收款 + 日报」导出。全国一份，每个区域再各导出一份，业务门店留空。Excel 里没有统计期间、收款类型和导出时间，所以上面这些参数要按当时的查询条件填写，不能从文件名猜测。

周次是周一。统计起日必须是这个周一，止日必须在这周之内。2026-11-01 至 2026-11-19 跨了好几周，系统会拒绝把它当成某一周。

同一周、同一范围，文件和元数据都相同：再导入不会新增。内容不同：默认拒绝，旧快照保持原样。确认要换一版时加 `--revision` 或勾选「保留旧快照并写入新修订」。旧行仍在历史里。

指标主表是服务管理报表的通用导出，不是首保/二保/新保/续保那 5 个明细按钮。周期列写着 `2026年Q4` 时，季度起日是 2026-10-01，截至日用 `--as-of`（导出当天的累计截止日）。达成率按分子分母加权。区域空着的行标成「无区域」，不会用门店表改归属。

督导原因在周报页面手填，开始是空的。

以后如果要自动下载，必须先读 [共享 DMS 浏览器约定](https://github.com/kaisonlau8/m-hero/blob/main/docs/SHARED_DMS_BROWSER.md)，复用现有浏览器锁，并和每天 08:30 的导出错开。现在调用采集函数会直接失败，避免并发导出。
